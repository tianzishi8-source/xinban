# 心版 · 圣经钥节背诵游戏

给初中生用的经文背诵小游戏，经文为新标点和合本（神版）。整套是一个静态网页，不需要编译。

- **闯关**：一关一节经文（长段落每两节一关）。
  - 普通训练：抄一遍（可跳过）→ 选词 → 拼词 → 找错 → 再选 → 再找 → 填空 → 认出处。
  - 高阶训练：只看出处，默写整节。
  - 过程中经文卡从石版慢慢变成发光的心版（林后 3:3）。
- **测试**：60 秒快问快答，题型有填空、下一句、出处、排序，有连击加分。
- **对战**：两队同屏抢答，或比赛拼整节经文。
  - 平板：两边同时点。
  - 电脑：蓝营按 1–4，橙营按 7–0。
- **每日作业**：带领者后台顶部为每个小组设“作业经文包”和“每天 N 关”。组员每天要先在作业经文包里过完 N 个新关卡（剩下不足 N 关时做完即可），完成前其他经文包的闯关和测试、对战、词汇都锁住；首页有今日作业进度条。在几个小组都有作业时逐个完成。“作业检查”里能看到每个组员当天新过了几关。不在任何小组的人没有作业。
- **温习摸底**：每天第一次进闯关，从这个经文包已经过的关卡里出约 6 道打字填空（优先出最近学的、星星少的、以前错过的）。答错的关卡在地图上变红，标“温习”；有待温习关卡时不能开新关，重新过一遍就自动解除。“作业检查”里能看到摸底成绩和还没补完的温习关。
- **只能自己打字**：经文不能复制，答题框不能粘贴或拖放；擦掉、挖空的位置只留空白，不留原字的印记，打错时也不会露出正确的字。
- **福音的定义**：在“祷文·信经·福音”里，18 行分三部分；先一行一关，再三行一关，最后第一部分、第三部分整段各一关，共 26 关。
- **心版榜**：两个板块——“全部”（所有登录用户，在“我的”里关掉“在总榜上显示我”的人除外）和“我的小组”（只在本组里看）。三个榜：星星榜、测验榜（按经文包分开排）、勤练榜，每个榜都有总榜、本周、今日。最上面显示我的名次和离前一名还差多少。只显示显示名、所在小组和成绩。
- **经文包**（首页“换经文包”）：
  - 书卷：每卷书一个包；只有一两节的小书合成「历史书精选」「诗歌智慧书精选」「先知书精选」「书信精选」。
  - 课程：《基督里的新生命1》《基督里的新生命2》各 12 课。
  - 祷文·信经·福音；搜索。
  - 原来的“资料”题库已并入对应书卷，重复的经文已删去（清单见 `docs/经文包整理_删除清单.md`）。
  - 以前用旧名（如“n1 背诵经文·第三课”）设的作业经文包仍然有效，会自动对应到新名字。
- **带领者后台**（`leader.html`）。

## 目录

```
index.html              整个游戏（页面、样式、脚本、经文数据都在这一个文件里）
assets/                 插画（WebP）
supabase/schema.sql     接入 Supabase 时用的数据表和权限
docs/后端交接说明.md     给做系统的人：怎么把“本机保存”换成真正的后台
```

## 本地打开

直接双击 `index.html` 就能玩。插画通过相对路径读取 `assets/`，所以两者要放在一起。

## 部署成网站

这是纯静态页面，放到任何静态托管上都能用：

- **GitHub Pages**：仓库 Settings → Pages → Source 选 `main` 分支根目录，保存后几分钟内生效。
- **Vercel / Netlify**：导入这个仓库，框架选 “Other / 无”，不需要构建命令，发布目录是根目录。

## 账号与数据

- **账号**：所有人用同一种账号。**登录名**（小写字母和数字，2–24 位，建好后不能改）加密码用来登录；**显示名**是别人在榜单和小组里看到的名字，随时可以改。可以在游戏首页“注册新账号”，邮箱选填；也可以“先当游客玩”，游客的进度只存在那台设备的浏览器里。登录后点顶栏的显示名打开“我的”：改显示名、邮箱、密码，开关“在总榜上显示我”，用邀请码加入小组或退出小组。闯关进度、练习时长、测验成绩都存在数据库，换设备也不丢。
- **三种身份**：
  - **普通用户**：所有功能都能用，关卡按顺序解锁，所在小组设了作业时先做作业。
  - **带领者**（由主账号指定）：自己使用时和普通用户一样；另外能在带领者后台建小组、看邀请码、按人数批量建账号（接着小组前缀编号，6 位数字初始密码）、看组员学习情况和造句、给组员改显示名和重置密码、把人移出小组。
  - **主账号**（只有 `teacher` 一个）：不受任何规则限制，任何关卡都能直接点开；能看所有小组；后台“全部用户”里能指定或取消带领者、把人加进小组。主账号也可以自己建小组带领。
- **带领者后台**：打开 `leader.html`（网站上是 `/xinban/leader.html`），用和游戏同一个登录名和密码登录。原来的老师专属链接换成 `leader.html#k=同一个钥匙` 仍然可用。
- **数据库**：Supabase（项目 `xinban`，新加坡机房）。`supabase/schema.sql` 和 `migrations_2026-11-2[36]_*.sql` 是旧结构的历史；`migrations_2026-11-28_users_groups.sql` 把它改成现在的结构：`users`（用户）、`groups`（小组）、`group_members`（组员），用户端函数 `user_*`，带领者函数 `leader_*`，主账号函数 `admin_*`。测试：`node --test supabase/tests/*.test.mjs`（本地 Postgres），`python3 tests/e2e/user_e2e.py`、`python3 tests/e2e/leader_e2e.py`（页面）。
  - 每人每天的练习时长只占一行，每关只占一行，每次测验一行，数据量很小。
  - 用户只能通过登录凭证调用函数读写自己的数据；带领者只能看到自己带的小组，不能管其他带领者和主账号的账号。
  - 练习时长的计算方式：页面在前台、并且最近 2 分钟内有操作才计时，按雅加达时间分天。
- 在 Claude 页面（artifact）里打开时连不了外部数据库，只能当游客玩。
