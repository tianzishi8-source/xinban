# 心版 · 后端交接说明

> **更新（2026-11-04）**：学生账号、老师后台、进度与时长记录已经做好并上线。
> - 数据库：`supabase/schema.sql`（实际部署的版本）
> - 学生登录：`index.html` 里“学生账号（Supabase）”一段
> - 老师后台：`teacher.html`
>
> 实际做法和下文第 2–3 节的原方案不同：学生不用 Supabase Auth 匿名登录，而是由老师生成账号和密码，登录后拿一个凭证，经由 `student_*` 函数读写。下文第 4 节“多人对战”尚未实现，仍可按原方案做。


这份说明写给接手做系统的人。目标是把现在“只存在本机浏览器”的数据，换成用 Supabase 做后台。完成后可以做到：

- 学生用**班级码 + 昵称**登录，不需要邮箱；
- 换设备进度不丢；
- 老师后台能看到全班每一关的星星和测试成绩；
- 对战时每个学生用自己的手机答题，老师的电脑投屏当主持端。

游戏本身（出题、闯关流程、画面）都已经写好，不需要改。要做的是：登录、存取数据、多人对战这三块。

## 1. 现状：index.html 的结构

`index.html` 是一个单文件页面，没有构建步骤，也没有用框架，都是原生 JS。

| 部分 | 说明 |
|---|---|
| `BOOKS` / `SRCS` / `DATA` | 经文库，写在 `/*DATA_START*/` 那一行。`DATA` 每条是 `[书卷序号, 章节, 待核对标记, 带挖空标注的经文, 来源序号[]]`，挖空词写成 `【词|类】` |
| `UNITS` | 当前经文包拆出来的关卡列表，每关的唯一键是 `UNITS[i].key`，例如 `"约 3:16"`；长段落分段时是 `"约 1:1-18#2"` |
| `store.get / store.set` | localStorage 的封装，所有本机数据都经过它 |
| `MEM` | `{ 关卡键: 普通训练星数 }` |
| `ADV` | `{ 关卡键: 高阶训练星数 }` |
| `TBEST` | 测试最高分 |

本机保存用到的键：

| localStorage 键 | 内容 |
|---|---|
| `xb4-mem` | MEM（闯关星星） |
| `xb-adv` | ADV（高阶星星） |
| `xb4-tbest` | 测试最高分 |
| `xb4-local` | 这台设备的测试成绩列表 |
| `xb-nick` | 昵称 |
| `xb5-pack` | 当前经文包 |
| `xb-mode` | 普通 / 高阶 |
| `xb-sound` | 声音开关 |
| `xb5-custom` | 老师导入的自定义经文 |

页面里还有一套在 Claude 平台运行时才生效的同步代码（`initClass`、`pushClass`、`pushProgress`、`renderBoard`、`openTeacher`、`renderTeacher`，都检查 `window.claude`）。接 Supabase 时，**就是把这几个函数换掉**，函数名和调用位置可以保持不变。

## 2. Supabase 准备（约 15 分钟）

1. 在 supabase.com 新建项目。
2. **Authentication → Sign In / Providers**：
   - 打开 **Anonymous Sign-ins**（学生用）；
   - 保留 **Email**（老师用）。
3. **SQL Editor**：把 `supabase/schema.sql` 整段粘贴进去执行。它会建好：

   | 表 / 函数 | 用途 |
   |---|---|
   | `classes` | 班级 |
   | `students` | 学生 |
   | `progress` | 闯关进度 |
   | `test_scores` | 测试成绩 |
   | `duel_rooms`、`duel_players` | 对战房间和队员 |
   | `join_class()` | 学生加入班级 |
   | `class_leaderboard()` | 班级榜 |

   所有表都开启了行级安全：学生只能写自己的数据，老师只能看自己班的数据。
4. **Project Settings → API**：记下 `Project URL` 和 `anon public key`。这两个可以公开写在前端，安全靠的是行级安全规则。
5. 老师账号：在 **Authentication → Users** 里手动建一个邮箱账号。然后登录页面，或在 SQL Editor 里替老师建班：

   ```sql
   insert into classes (code, name, teacher_id)
   values ('CHU2A', '初二一班', '<老师账号的 user id>');
   ```

## 3. 前端接入

### 3.1 引入 supabase-js

在 `index.html` 的主脚本 `<script>` 之前加：

```html
<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2.45.4/dist/umd/supabase.js"></script>
<script>
  const SB = supabase.createClient("https://你的项目.supabase.co", "你的 anon key", {
    auth: { persistSession: true, autoRefreshToken: true }
  });
</script>
```

### 3.2 登录界面（需要新增）

**学生：**
1. 首页顶部加一个“加入班级”入口：输入班级码和昵称。
2. 调用：
   ```js
   await SB.auth.signInAnonymously();
   const { error } = await SB.rpc("join_class", { p_code: code, p_nickname: nick });
   // error.message 可能是“班级码不存在”，或昵称重复（unique 冲突）→ 提示换名字
   ```
3. 登录状态由 supabase-js 存在浏览器里，下次打开会自动恢复。

**老师：**
1. 在“老师后台”入口加邮箱密码登录：
   ```js
   await SB.auth.signInWithPassword({ email, password });
   ```
2. 判断是否为老师：
   ```js
   (await SB.from("classes").select("id").limit(1)).data.length > 0
   ```

### 3.3 逐个替换的函数

| 现在的函数 | 什么时候被调用 | 换成 |
|---|---|---|
| `initClass()` | 页面加载末尾 | 恢复登录状态；读 `progress` 合并进 `MEM` / `ADV`（取较大值）；读 `max(score)` 合并进 `TBEST`；判断是不是老师，显示“老师后台”按钮 |
| `pushProgress()` | `finishLevel()` 过关后 | `upsert` 当前这一关（见下方示例），只写变化的那一行，不要整包上传 |
| `pushClass()` | `endTest()` 测试结束、过关后 | `endTest` 里改为 `insert` 一行 `test_scores`；过关时不需要调 |
| `renderBoard()` | 打开心版榜 | `SB.rpc("class_leaderboard")`，字段：`nickname`、`best_score`、`passed`、`is_me` |
| `openTeacher()` / `renderTeacher()` | 老师后台 | 读本班 `students` + `progress` + `test_scores`，组装成现在的表格结构（`tag`、`lv`、`best`、`at`） |

`pushProgress` 的示例：

```js
await SB.from("progress").upsert({
  student_id: uid, unit_key: u.key,
  stars: MEM[u.key] || 0, adv_stars: ADV[u.key] || 0,
  updated_at: new Date().toISOString()
});
```

注意：`finishLevel()` 里在分段经文全部过关时，会额外写一个整节的键（`MEM[u.v.ref]`），这一行也要一起 upsert。

### 3.4 第一次登录时迁移本机进度

学生在登录前可能已经在本机玩过。第一次 `join_class` 成功后，把 localStorage 里的 `MEM` / `ADV` 批量 upsert 上去（一次请求传数组），然后以服务器数据为准。

### 3.5 离线和失败

- 写库失败时先照常写 localStorage，记一个“待同步”标记，下次打开或联网时重试。
- 游戏流程不要等网络返回，保持现在的手感。

## 4. 多人对战（每人一部手机）

用 Supabase Realtime 的**广播频道**传题目和答案，不逐题写数据库。

**角色：**
- 主持端：老师的电脑接投影，负责出题、判定、计分，是唯一的裁判。
- 选手端：学生的手机，只显示自己队伍的选项按钮。

**流程：**

1. **开房（主持端）**：生成 4–6 位数字房间码，`insert` 一行 `duel_rooms`（`class_id`、`code`、`pack`）。投影上显示房间码。
2. **加入（选手端）**：输入房间码，`insert` 自己到 `duel_players`，选择蓝营或橙营（也可以由主持端自动分队）。
3. **双方订阅频道** `duel:<房间码>`：
   ```js
   const ch = SB.channel("duel:" + code, { config: { broadcast: { self: false } } });
   ch.on("broadcast", { event: "question" }, ...).subscribe();
   ```
   用 Presence 显示在线人数。
4. **出题（主持端）**：用现有的 `makeQ(LIB, true)` 出题，广播 `question`：`{ qid, type, html, opts, endsAt }`。
5. **作答（选手端）**：点选项后广播 `answer`：`{ qid, team, student_id, choice, t }`。
6. **判定（主持端）**：沿用现在 `dqNext()` 的规则。
   - 某队有人答对，该队得 1 分，本题结束。
   - 答错的人本题锁定。也可以改成整队锁定，按现有逻辑是“答错这一队本题不能再答”。
   - 判定后广播 `result`：`{ qid, winner, scoreA, scoreB, answer }`，然后出下一题。
7. **结束**：先到 7 分得胜，更新 `duel_rooms.status = 'finished'` 和比分，广播 `end`。

**说明：**
- 判定只在主持端做，选手端只负责显示和提交，所以选手改代码也作弊不了得分。
- v1 可以用公开频道，房间码就是“口令”。更严格时改用 Realtime 的私有频道，在 `realtime.messages` 上加 RLS，只允许 `duel_players` 里的人订阅。
- 现有的同屏对战（平板同时点、键盘 1–4 / 7–0）保留，作为不联网时的方案。

## 5. 需要留意的地方

- **匿名账号和浏览器绑定**：学生清理浏览器数据后，再登录会变成一个新账号，原来的昵称在班里已被占用。
  - 简单方案：老师后台提供“释放昵称 / 合并进度”。
  - 更稳的方案：老师给每个学生发一个 4 位 PIN，加入时验证。可以在 `students` 加一列 `pin_hash`，`join_class` 里校验。
- **老师导入的自定义经文**（`xb5-custom`）目前只存在老师本机。如果要全班共用，新建一张 `custom_verses` 表，按 `class_id` 归属。
- **经文版权**：新标点和合本有版权方。公开上线前请确认使用许可。
- **数据量**：一个学生最多几百行 `progress`，一个班几十人，免费额度足够。

## 6. 验收清单

- [ ] 学生用班级码 + 昵称登录，刷新页面后仍是登录状态
- [ ] 在手机上过一关，在电脑上用同一账号打开，星星一致
- [ ] 测试成绩出现在心版榜上，只显示本班同学
- [ ] 老师后台能看到全班每关的星星和测试最高分；学生看不到别人的进度
- [ ] 断网时还能正常玩，联网后进度补传
- [ ] 对战：老师开房，5 部手机分两队加入，抢答判定和计分正确，结束后比分写入 `duel_rooms`

## 2026-11-06 更新（二）：老师专属链接、按 班级+名字 的账号
- 老师后台可以用专属链接打开：`teacher.html#k=<钥匙>`，打开一次后浏览器会记住，不用登录。钥匙只以 sha256 哈希存在 `private.teacher_keys`，页面通过请求头 `x-teacher-key` 传给数据库，`private.me()` 据此识别老师（已登录时仍用 auth.uid()）。
- 钥匙不写进仓库。需要换钥匙时：在 `private.teacher_keys` 删掉旧行、插入新钥匙的哈希。
- 学生账号允许 `g7samuel` 这类形式（小写字母数字 2–24 位）；游戏登录框会去掉空格、转小写，所以输入 “G7 Samuel” 也能登录。
- 班级列表改由 `teacher_classes()` 读取；新生成和重置的密码改为 4 位数字。

## 2026-11-06 更新（三）：作业检查
- 新表 `public.plays`：学生每过一关记一条（经文、普通/默写、星数、失误、时间），游戏端 `cloudPlay()` 排队后经 `student_save_plays` 上传。
- `usage_daily` 新增 `first_at`/`last_at`，用于显示每天练习的时间段。
- 老师端：`teacher_day(班级, 日期)` 供“作业检查”页；`teacher_student_days(学生, 天数)` 供学生详情里的“最近一周每天的记录”。
- “作业要求：每天至少 N 分钟”存在老师浏览器本地，默认 15 分钟。

## 2026-11-07 更新：英文 ESV 版
- 首页可切换“中文 和合本 / English ESV”。英文版经节范围与中文相同，出处如 `John 3:16`；进度、过关记录的键就是英文出处，和中文分开记。
- 英文经文经 Supabase 边缘函数 `esv`（源码 `supabase/functions/esv/index.ts`）取用：先查 `public.esv_cache`，没有再向 ESV API 取，取到后存入缓存。ESV 密钥在 `public.esv_config`，两表都开了 RLS、对 anon/authenticated 无权限，只有边缘函数（service role）能读写。
- ESV API 应用：Xinban Scripture Memory（api.esv.org，非商业网站，已批准）。规则：每次查询 ≤500 节，每天 5000 次 / 每小时 1000 次 / 每分钟 60 次；本地存储不超过连续 500 节或半卷书；每页显示 ESV 版权声明并链接 esv.org。
- 游戏端：英文按“词”处理（中文按“字”）。`tok/isW/nrm/units/matchTyped` 统一两种语言；挖空词自动选实词（去掉常用虚词），找错题用 `ENSYN` 近义词表；浏览器本地只留最近约 400 条英文经文。

## 2026-11-12 更新：补全句子、主祷文/使徒信经、对战升级
- 普通训练里的两次“校（找错）”换成“补（补全句子）”：擦掉经文里一句含核心词的话让学生补写；提示一露出非核心词 2 秒，提示二露出整句 3 秒（扣一次星）；写对自动通过，写错只在点“确定”时判。
- 新经文包“祷文·信经”：主祷文、使徒信经，中英文各一套，数据在 `TEXTS`。关卡按行逐级：中文主祷文 单行→两行→三行→全文；英文主祷文 两行→四行→八行→全文；使徒信经（中英）单行→两行→四行→全文。最后一组与已有关卡重复时改为取最后几行（有重叠）。出处键形如 `主祷文 L1-2`、`The Lord's Prayer Full`，后台按书卷归组。这些关最后一步是“盖印”，测验里不出“出处”题。
- 对战：开场 3-2-1 倒计时；WebAudio 合成背景音乐（`BGM`），比分越接近终点越快；抢答每题 12 秒倒计时；得分时屏幕震动，赛点提示；竞技场配色。
